# specs/ — 스펙 주도 개발 (SDD)

기능 추가나 의미 있는 변경은 코드보다 **스펙을 먼저** 쓰고, `02_plan.md` 를 **사용자가 승인한 뒤** 구현에 들어간다.

규칙의 출처는 루트 [`AGENTS.md`](../AGENTS.md) 5장이다. 이 문서는 폴더를 열었을 때 절차를 바로 알 수 있게 둔 것이다.

## 폴더 규칙

작업마다 폴더를 하나 만든다: `specs/YYYY-MM-DD-<슬러그>/`
예) `specs/2026-08-08-company-standards-adoption/`

- 날짜가 **앞**에 온다 — 폴더 목록이 그대로 시간순이 된다.
- 슬러그는 영어 소문자 + 하이픈.
- 폴더명의 날짜는 **작업 시작 시점을 가리키는 식별자**다. 나중에 고치지 않는다 (AGENTS.md 8장의 "문서 제목에 날짜 금지" 예외).

[`_template/`](_template) 을 복사해서 시작한다. 폴더 안에는 4개 문서를 둔다.

| 문서 | 용도 | 언제 쓰나 |
|---|---|---|
| `01_README.md` | 목적·배경·범위 | 시작 전 |
| `02_plan.md` | 접근·단계·검증 **(승인 게이트)** | 시작 전 |
| `03_progress.md` | 시간순 작업 로그 + Reboot Check | 작업 중 계속 |
| `04_notes.md` | 결정·이유·함정 | 작업 중 계속 |

## 흐름

1. `01_README.md` + `02_plan.md` 작성
2. **사용자 승인** ← 이 게이트를 통과하기 전에는 구현하지 않는다. `02_plan.md` 의 승인 칸에 표시한다
3. 작은 단위로 구현
4. 한 단위가 끝날 때마다 `02_plan.md` 체크리스트와 `03_progress.md` 를 갱신한다 — **요청 없이도.** 몰아서 일괄 갱신은 금지
5. 결정·함정이 생기면 그때 `04_notes.md` 에 적는다
6. 세션이 끝날 때 `03_progress.md` 의 **Reboot Check** 를 갱신한다

## 작성 규칙

- **`01_README.md`** — 목적과 범위만. 클래스명·함수명·API 경로를 넣지 않는다. 나중에 읽는 사람이 "무엇을 왜 하려 했나"를 알면 된다.
- **`02_plan.md`** — 실제 코드 블록을 넣지 않는다. 의사코드·설명·표로 쓴다. 파일 경로와 검증 명령은 넣어도 된다.
- **`03_progress.md`** — 시간순(오래된 → 최신)으로 쌓는다. 같은 날짜는 하나로 합친다. **테스트·검증 결과는 최신 결과로 덮어쓴다(누적 금지)** — 낡은 결과가 쌓이면 어느 게 지금 상태인지 알 수 없다. 해결된 환경·설정 문제는 이력으로 남기지 않는다.
- **`04_notes.md`** — 결정은 **결정 / 이유 / 대안** 3점 세트로 적는다. 결정만 적으면 나중에 왜 그랬는지, 무엇을 검토했다 버렸는지가 사라진다. 시도 과정 전체가 아니라 **교훈만** 추린다.
- 내용을 추가할 때는 해당 섹션의 **맨 마지막**에 붙인다. 주제가 비슷하다는 이유로 기존 항목 사이에 끼워 넣지 않는다.

## 탐색

코드베이스를 넓게 훑어야 하면 `Explore`/`Plan` 서브에이전트에 위임하고 결과만 받는다 (메인 컨텍스트 절약). 경로를 이미 아는 단일 파일 확인·템플릿 읽기·문서 작성은 직접 한다.
