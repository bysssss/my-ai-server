## 단계

### 0. 기본 정비

### 1. 규칙층 — 루트 AGENTS.md

- [x] **번호 체계화** (1장~N장). 다른 모든 개선의 전제 조건 — 지금은 평문 헤딩이라 규칙 인용이 불가능하다.
- [x] **"이 프로젝트에서 안 하는 것"** 목록을 맨 뒤에 추가 — 금지 사항을 장 번호와 함께 한곳에 모아 회수(recall)를 쉽게 한다.
- [x] **검증 명령 섹션** 추가 — 코드 변경 후 최소 검증 명령(ruff / pytest / build). 지금은 Makefile 에만 있고 문서에는 없다.
- [x] **Active Path Rule** 추가 — 구현 위치가 실제로 호출되는 경로인지 코드로 확인한다 (죽은 코드에 구현하는 것 방지). 현재 Code Reading Protocol 에 빠져 있다.
- [x] **프레임워크 버전 함정 섹션** 추가 — 에이전트 학습 데이터가 구버전 기준일 때의 주의. esign 의 "Spring Boot 4 주의사항"에 대응하는 자리를 FastAPI/Pydantic 기준으로 만든다.
- [x] **한국어 표현 규칙 보강** — 구어·과장 표현 금지 표, 조사 붙여쓰기 규칙.
- [x] **설정 파일에 "왜"를 주석으로 적는다** 규칙 추가 — 무엇이 아니라 왜만. esign 은 빌드 설정·CI 설정 옆에 이유가 붙어 있어 나중에 그 값을 바꿔도 되는지 판단할 수 있다. 우리 `settings.json`·`Makefile` 은 주석이 얕다.
- [x] **PR 루프 규칙** 추가 (Git 절) — 지금은 절차 자체가 없다. 스펙 승인 → 구현 → 커밋 → PR → **관련 문서 갱신을 같은 PR 에 포함**(별도 문서 PR 을 만들지 않는다. 머지 시점에 코드와 문서가 한 번에 맞는다) → 리뷰 지적을 코드로 검증한 뒤 반영하거나 근거를 들어 유보 → 새 지적이 없을 때까지 반복 → **머지는 사용자가 한다.**
  - AI 리뷰 도구(CodeRabbit 등) 연동은 보류 항목이다. 도구 없이도 절차는 성립하므로 규칙만 먼저 적는다.
- [x] **"미래 요구를 미리 반영하지 않는다"** 추가 — 현재 규칙은 "요청하지 않은 모듈·엔드포인트를 만들지 않는다"까지다. 한 줄 더 세게: 가장 단순한 방법으로 한 가지 문제만 해결하고, 나중에 필요할 것 같다는 이유로 미리 만들지 않는다.
- [x] **예시 코드 작성 규칙** 추가 — 문서·주석에 예시를 쓸 때 실제 클래스명·비즈니스 로직을 복사하지 않는다. 범용 이름으로, 누가 봐도 예시임을 알 수 있게 최소한만.

### 2. 규칙층 — backend/AGENTS.md (API · 시간 · 식별자)

셋 다 현재 문서에 **없다.** 회사 표준을 그대로 쓰지 않고 두 곳을 바꾼다 (근거는 `04_notes.md`).

- [x] **API 설계** — 복수형·kebab-case 경로, 쿼리 파라미터는 camelCase, 목록으로 접근할 수 없는 자원은 단수형.
      **`PUT`/`PATCH` 는 통일하지 않는다** (회사는 `PATCH` 로 통일) — 전체 교체는 `PUT`, 부분 수정은 `PATCH`, 애매하면 `PATCH`.
- [x] **시간** — UTC 저장 / 응답은 ISO 8601. 파이썬에서의 핵심은 naive datetime 금지 (`datetime.now()` 대신 `datetime.now(timezone.utc)`).
- [x] **식별자** — **UUIDv7** (회사는 ULID). 표준 라이브러리 `uuid.uuid7()` 은 Python 3.14 부터라, 3.12 인 지금 도입하면 `uuid-utils` 같은 패키지가 필요하다.
- [x] **파라미터 재할당 금지** — 파라미터에 다시 대입하지 않고 다른 이름의 새 변수에 담는다. 원래 들어온 값이 무엇이었는지 추적이 끊긴다.
- 시간·식별자 규칙은 **지금 적용할 코드가 없다** (DB·엔티티 없음). 규칙만 먼저 세우는 것이므로 `docs/standards-adoption.md` 에는 "규칙만 있고 적용 대상 코드는 아직 없음"으로 적는다 — 적용했다고 착각하지 않기 위해서다.

### 7. 게이트 — CI (GitHub Actions)

지금은 `main` 에 push 하면 **아무 검사 없이** Cloudflare Pages 가 바로 빌드·배포한다. 테스트도 lint 도 돌지 않는다. 검사층이 없다.

- [x] `.github/workflows/ci.yml` 신설 — PR 과 `main` push 마다 **검사만** 한다. 배포는 종전대로 Cloudflare Pages(자동)·Cloud Run(수동)이 맡는다. 검사와 배포를 한 파일에 섞지 않는다.
- [x] backend job — uv 설치 → `uv run ruff check` → `uv run pytest`
- [x] frontend job — `npm ci` → `npm run lint` → `npm run build` (`tsc -b` 라 타입 검사까지 함께 돈다)
- [x] 각 단계에 **왜 이 검사가 있는지** 주석을 단다 (1단계의 "왜" 주석 규칙 적용).
