# 회사 표준 2차 반영 (team-pulse · esign-service)

> 회사 두 레포에서 **언어 중립인 규칙·절차·게이트 층**만 골라 my-ai-server에 반영한다.

## 목적 / 배경

- 1차 조사는 2026-07-12에 했고, 결과는 `docs/agentic.md` 의 "회사 표준과의 관계" 섹션에 남아 있다 (채택 4 / 의도적 차이 3 / 보류 3).
- 이번은 **2차**다. 1차에서 빈 두 지점을 메운다.
  - **team-pulse 미조사** — 1차 대상은 member-api·esign-service 뿐이었다. 전사 개발표준과 문서 위생 규칙이 여기 있다.
  - **esign-service 의 그 이후** — 1차 때 "보류"한 CI 게이트·PR 루프를 회사가 그 뒤 실제로 만들었다 (커버리지 게이트 2026-08-07, `ci.yml` 2026-08-08). 참고할 실물이 생겼다.
- 회사는 Java/Spring 이라 **코드는 참고 대상이 아니다.** 가져오는 것은 규칙·절차·게이트뿐이며, 그 층은 언어와 무관하다.

## 두 레포의 성격

| 레포 | 성격 | 여기서 가져올 것 |
|---|---|---|
| team-pulse | 회사 공통 도메인·전사 표준을 정리하는 문서 레포 | 개발표준 3축(API·시간·식별자 — 두 곳은 고쳐서), 문서 제목 날짜 금지 |
| esign-service | 사용자가 개발하는 서비스. AI 개발 셋팅이 가장 진화한 레포 | AGENTS.md 구조, review 스킬, specs 작성 규칙, 표준 추적 문서 |

## 범위

- 포함:
  - **규칙층** — AGENTS.md 번호 체계화, 누락 원칙 보강, API·시간·식별자 3축
  - **절차층** — specs 작성 규칙, review 스킬 신설, 스킬 형식 통일, 문서 제목 날짜 금지
  - **기록층** — 표준 적용 현황 문서 (무엇을 **왜 안 했는지**까지)
  - **결함 수정** — 루트가 참조하는데 없는 `frontend/AGENTS.md`
- 제외 (결정이 필요해 이번엔 안 함 — `02_plan.md` "보류" 참조):
  - CI 게이트 도입, 커버리지 게이트 / TDD 명문화
  - 아키텍처 as code(Structurizr), 프론트엔드 FSD 체계
- 가져오지 않는 것 (판단 완료 — 근거는 `04_notes.md`):
  - Java/Spring 전용 코딩 규칙 (Lombok·JPA·`ResponseEntity` 등) — 스택 전용
  - **에이전트 메모리 금지** — 회사 규칙이지만 my-ai-server 는 메모리 활용 자체가 시연 대상이라 반대로 간다
  - **`PATCH` 통일** — 두 메서드는 의미가 다르다. 레퍼런스 레포에서 의미를 뭉갤 이유가 없다
  - **ULID** — 대신 UUIDv7 을 쓴다
  - **표준 분리 구조** — 레포 하나에 1인이라 전사 표준과 레포 규칙을 나눌 이유가 없다
  - **살아있는 문서 vs 불변 스냅샷 구분** — 받은 원본을 쌓는 레포가 아니다
  - **`.gitattributes`** — esign 것은 `gradlew`·`.bat` 개행 처리용이다. 파이썬/TS 에는 해당 없다
  - **`docs/operations.md`** — 우리 `docs/infra.md` 가 이미 같은 자리를 채우고 있다
  - **릴리스 워크플로(dev/stg/prod 태그 승격)** — 환경이 하나뿐이라 과하다
  - Jira 티켓 규칙, 팀원 명부 — 1인 프로젝트에 무의미
