# 노트 (결정·함정·왜)

> 시간순 로그는 `03_progress.md`. 여기는 누적 참고용 — 다음에 또 헤매지 않도록 "왜 이렇게 했나"와 함정을 적는다.

## 결정

- **결정**: 커밋·푸시 승인 게이트를 제거하고, 스펙 승인이 그 범위의 커밋·PR·재수정까지 포함하게 한다.
  - **이유**: 커밋마다 사람이 끼면 개발→테스트→리뷰→재수정 자동 루프가 매번 끊긴다. 1인 프로젝트고, 잘못된 커밋은 PR·CI가 걸러주고 머지 전에 사람이 본다 — 게이트가 이중이다.
  - **대안**: 회사 규칙 유지(커밋마다 승인) — 다인 팀에는 맞지만 여기선 병목만 남는다고 판단해 버렸다.
- **결정**: specs 는 보관하되 6개월 기간제로 지운다. 지우기 전 유효한 결정·함정은 docs 로 옮긴다.
  - **이유**: 작업 당시 히스토리는 남겨야 한다(사용자 요구). esign 이 겪은 "낡은 문서가 사실처럼 보이는" 문제는 유효 사실을 docs 로 승격하는 것으로 예방한다. 지워도 git 에 영구히 남는다.
  - **대안**: esign 방식(즉시 폐기, 레포 밖 작업 폴더) — 히스토리 접근성이 떨어져 버렸다. property-right 방식(무기한 보관) — 25폴더쯤에서 신뢰 문제가 재현될 것이라 기간을 뒀다.
- **결정**: 커버리지 게이트를 "테스트 쌓인 뒤"에서 "지금"으로 앞당긴다.
  - **이유**: property-right 의 역발상 — "코드가 거의 없는 지금 시작하므로 지킬 수 있다. 한 번 낮추면 올리는 시점이 오지 않는다." 코드가 health 하나뿐인 지금이 높은 기준을 걸 유일한 시점이다.
  - **대안**: 기존 계획(테스트 쌓인 뒤 측정, 측정값보다 낮게) — 이미 쌓인 코드가 있는 esign 상황의 논리라, greenfield 인 여기엔 property-right 논리가 맞다.

## 함정 (gotcha)

- **자율 루프의 비결을 도구에서 찾지 마라.** urbanzone 조사 전 가설은 "특별한 스킬이나 CodeRabbit 설정이 있을 것"이었는데, 실제로는 아무것도 없었다. 루프는 AGENTS.md 의 문장("사용자 요청 없이도 갱신", 게이트 2곳)과 specs 에 쌓인 선례가 만든다.
- **장 번호 인용은 장 삽입에 깨진다.** property-right 실사례 — AGENTS.md 앞에 1·2장을 끼워 넣자 스킬들의 "12장" 인용이 실제 14장을 가리키게 됐다. 번호 체계를 쓰는 한 "장 추가·삭제 시 인용 전수 점검"이 세트다.
- **서브에이전트 보고도 틀린다.** urbanzone 조사 에이전트가 "my-ai-server 에도 docs-sync 스킬이 있다"고 보고했는데 실제로는 없다. 보고를 그대로 믿지 말고 로컬 사실은 직접 확인한다.
