# 자율 파이프라인 완성 — 커밋 게이트 제거와 PR 이후 절차

> 스펙 승인부터 머지 직전까지 사람 개입 없이 도는 파이프라인을 완성한다. 3차 조사(urbanzone·property-right·esign·team-pulse)의 반영분.

## 목적 / 배경

- 3차 조사 결과, 자율 루프의 뼈대(승인 게이트·계획서 직렬화·PR 루프·CI)는 이미 있다. 남은 병목이 둘이다.
  - **커밋 승인 게이트** — 커밋마다 사람이 끼면 개발→테스트→리뷰→재수정 루프가 매번 끊긴다. 1인 프로젝트고 PR·CI가 뒤에서 걸러주므로 이 게이트는 병목만 된다.
  - **PR 이후 절차 부재** — 스킬이 PR 생성에서 끝난다. CI가 깨져도, 리뷰가 달려도 다음 세션의 AI는 대응 절차를 모른다.
- 목표 상태: **사람 = 스펙 승인(입구) + 머지(출구)**, 그 사이(개발·테스트·커밋·PR·CI 대응·재수정)는 전부 자동.
- 함께 반영: 조사에서 나온 소소한 보강 3건 (커버리지 게이트 / 장 번호 점검 / specs 보관 규칙).

## 범위

- 포함:
  - 커밋·푸시 규칙 변경 — 스펙 승인 = 커밋·PR까지 포함 승인
  - create-pr 스킬에 PR 이후(CI 초록·리뷰 대응·머지 가능 보고) 절차
  - 커버리지 게이트 (backend pytest / frontend vitest 없음 → backend만, CI에 연결)
  - AGENTS.md 장 번호 인용 점검 규칙
  - specs 보관 규칙 (6개월 후 삭제, 유효 사실은 docs 승격 후)
- 제외:
  - CodeRabbit 연동 — 아직 미연동. 리뷰 대응 절차는 규칙으로만 준비해 둔다
  - 아키텍처 패턴(이벤트 봉투·Outbox·인가) — 해당 코드가 없다. 백로그에만 기록
- 하지 않기로 한 것 (판단 근거는 `04_notes.md`):
  - specs 폐기(esign 방식) — 히스토리 보관 요구. 기간제 삭제로 대체
